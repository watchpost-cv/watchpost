# Phase 3 cluster extraction evidence

Phase 3 extracts only the generic behavior proven by Watchpost CP9-CP17 and then rebases Watchpost onto that package.

## Result

Watchpost now consumes `github.com/gantry-tools/gantry-core/cluster` for:

- node identity value types, fingerprinting and cryptographic identity generation;
- protocol and pairing/rotation constants;
- capability normalization and protocol/capability compatibility;
- invitation values, pairing transition validation, credential generation and digests;
- canonical request signatures and incoming credential/signature verification;
- target parsing, bounded parallel fan-out and deterministic per-node result envelopes.

Watchpost retains:

- SQLite schema, migrations, transactions and nonce persistence;
- Watchpost audit records and authorization;
- member persistence and rotation writes;
- HTTP route registration and existing `X-Watchpost-*` header names;
- monitor, Agent, check, alert and incident ownership/summary policy;
- Agent pairing and human accounts.

No database replication, shared human authentication, consensus or configuration propagation was introduced.

## Compatibility coverage

CP26 adds explicit coverage that:

- a schema-15-style pre-cluster database migrates through the clustering schemas without losing an existing Agent pairing;
- local cluster node identity survives database close/reopen;
- the Watchpost and Gantry Core protocol versions agree;
- an incompatible protocol version is refused rather than downgraded.

Existing CP17 coverage continues to exercise invitation expiry/single use, replay rejection, revocation, credential rotation overlap, duplicate installation identity, partial fan-out, standalone operation, removal and re-pairing.

## Validation performed in this workspace

Gantry Core:

```text
GOWORK=off go test ./...
GOWORK=off go test -race ./cluster
GOWORK=off go vet ./cluster
```

All passed.

The execution environment supplies Go 1.23.2 and blocks the Go module/toolchain proxy, while Watchpost declares Go 1.25.0 and its normal SQLite driver is not cached. For executable Watchpost validation, an uncommitted validation copy lowered only the temporary module's Go directive to 1.23 and replaced `modernc.org/sqlite` with a small validation-only `database/sql` driver backed by the system SQLite library. The delivered Watchpost source, `go.mod`, SQLite driver and schema were not changed for this workaround.

Against that copy:

```text
go test ./internal/store ./internal/cluster
go test -race ./internal/store ./internal/cluster
go vet ./internal/store ./internal/cluster
```

All passed. A separate dependency-light type-check copy also compiled the production `internal/cluster` package against the local Gantry Core checkout.

The broader Watchpost server/CLI wall could not be executed in this sandbox because uncached unrelated dependencies (`gosnmp`, `x/net`, `x/sys`, `go-humanize`) require the blocked module proxy. The top-level `go.work` generated by Gantry Core's workspace script is included so a normal Go 1.25 development environment resolves Watchpost against this exact local Gantry Core checkout.
